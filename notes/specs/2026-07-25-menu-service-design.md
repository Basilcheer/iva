# Меню «Обслуживание» (/menu → 🛠) — дизайн

Дата: 2026-07-25. Статус: утверждено на словах, ждёт ревью текста.

## Цель

Технические команды инсталляции — доктор, чистка vault, ночной цикл памяти, обновление —
доступны из Telegram без SSH: отдельный экран «🛠 Обслуживание» во вложенном меню `/menu`.
Каждая команда показывает живой прогресс анимированным эмодзи и заканчивается краткой сводкой.

## UX

### Корневой экран

Пара `[📊 Статус] [🛠 Обслуживание]`, «✖ Закрыть» уезжает в отдельный ряд:

```
[🧠 Модель]    [🤔 Размышления]
[🔍 Поиск]     [🌐 Язык]
[🎭 Характер]  [💾 Память]
[📡 Userbot]   [🔗 Google]
[⏰ Кроны]     [🧩 Скиллы]
[📊 Статус]    [🛠 Обслуживание]
[✖ Закрыть]
```

### Экран «Обслуживание» (sid `svc`)

```
🛠 Обслуживание

Диагностика и уход за инсталляцией.

[🩺 Доктор]        [🧹 Чистка vault]
[🌙 Ночной цикл]   [🔄 Обновление]
[‹ Назад]
```

- **🩺 Доктор** — `iva doctor`: диагностика и авто-починка (юниты, таймеры, порт, .env, сборка).
- **🧹 Чистка vault** — `cleanup.py --apply`: стриминговая чистка раздутых файлов (фикс 0.3.1).
- **🌙 Ночной цикл** — ручной запуск `iva-memory-doctor.service`, не дожидаясь 05:00
  (sync скриптов → cleanup → enforce → graph → git push).
- **🔄 Обновление** — хендофф в существующий `/update`-флоу (проверка → кнопки
  Обновить/Пропустить → transient-юнит, переживающий рестарт моста). Ничего нового не строим.

### Флоу команды (кроме Обновления)

1. Тап по команде → **экран подтверждения**: что сделает, типичная длительность,
   `[▶ Запустить] [‹ Назад]`.
2. `▶ Запустить` → то же сообщение превращается в **живой прогресс**:
   анимированный эмодзи + текущий шаг + прошедшее время, кнопка `[✖ Отменить]`.
3. Финал → **сводка** (✅/⚠️ + цифры команды) + `[‹ Назад]`.

Обновление: тап вызывает `handleUpdateCheck(chatId)` — статус приходит отдельным сообщением
(как при ручном `/update`), меню остаётся на экране «Обслуживание».

## Анимированные эмодзи

Набор тот же, что у `/update` и working-status: `LoadingStatusByTimDesign`
(в коде уже есть 🟩 `5256127530271786963` у апдейта и 🔵 `5258372840389888502` у working-status —
оба id первые в своей цветовой группе набора; новые берём той же логикой).
Квадраты = «системные операции» (как update), синий круг остаётся за «Ива думает».

| Команда      | alt | custom_emoji_id     | fallback |
| ------------ | --- | ------------------- | -------- |
| Доктор       | 🟥  | 5255894270597941229 | ◇        |
| Чистка vault | 🟨  | 5255975857796695002 | ◇        |
| Ночной цикл  | 🟪  | 5256218768262056531 | ◇        |
| Обновление   | 🟩  | 5256127530271786963 | ◇        |

(строка «Обновление» — существующий флоу со своим лоадером, не трогаем; в таблице для полноты.)

Механика — как `editActive` в `scripts/lib/telegram-status.mjs`: entity `custom_emoji`
на alt-эмодзи; при 400 от Telegram (владелец бота без Premium) — одноразовый глобальный
даунгрейд на fallback-символ. Реализация — локальный хелпер внутри экрана `svc`
(существующие две реализации не рефакторим — вне скоупа).

Кастомное эмодзи анимируется на клиенте само — редактировать сообщение ради «кадров»
не нужно. Редактируем только при смене текста и для тика времени: не чаще раза в ~3 с,
пропуская идентичные payload'ы (паттерн `lastPayload` из telegram-status).

## Архитектура

Новый модуль `scripts/lib/menu/service.mjs` (sid `svc`), регистрация в `SCREENS`
(`scripts/lib/menu/index.mjs`), кнопка в `root.mjs`. Каждой команде — свой механизм запуска:

| Команда      | Механизм                                                                |
| ------------ | ----------------------------------------------------------------------- |
| Доктор       | `spawn(node, [bin/iva.mjs, doctor])` из моста, cwd=ROOT                 |
| Чистка vault | `spawn(uv, [run, cleanup.py, ., --apply])`, cwd=vaultDir                |
| Ночной цикл  | `systemctl --user start --no-block iva-memory-doctor.service` + поллинг |
| Обновление   | хендофф `deps.handleUpdateCheck` (transient-юнит уже есть)              |

Обоснование гибрида:

- `iva doctor` рестартует сервисы **только упавшие** — живой мост он не тронет; spawn безопасен.
- Дети моста живут в его cgroup — при рестарте моста systemd убьёт и их. Это честно:
  прогресс без хозяина не осиротеет.
- Ночной цикл через его же юнит = тот же env/lock, что ночью; переживает рестарт моста.
  Юнит `Type=oneshot` → старт с `--no-block`, статус поллингом `is-active` каждые 3 с:
  `activating` — идёт, `inactive` — успех, `failed` — провал.

### Прогресс и вывод

- stdout/stderr детей копим в кольцевой буфер, ANSI-коды стрипаем.
- Текущий шаг: последняя непустая строка stdout (доктор печатает шаги ✓/⚠/✗,
  cleanup — по строке на файл).
- У ночного цикла шагов нет — показываем прошедшее время; итог — `Result`/`ExecMainStatus`
  из `systemctl show` + хвост `journalctl --user -u iva-memory-doctor.service` (~15 строк).

### Сводки

- **Доктор**: exit 0 → «✅ Диагностика пройдена», иначе «⚠️ Есть проблемы»; + хвост вывода
  (стрипнутый, до ~1 500 символов — запас от лимита 4 096 у editMessageText).
- **Чистка**: парсим финальную строку `cleanup (apply): N file(s), X bytes…` →
  «✅ Чистка: N файлов, X МБ мусора убрано»; не распарсилось — хвост вывода как есть.
- **Ночной цикл**: «✅ Цикл памяти пройден за M мин» / «⚠️ Цикл упал — хвост журнала: …».

### Конкурентность и защита

- **Один процесс за раз**: module-level busy-флаг `{cmd, chatId, startedAt}`.
  Тап по любой команде при занятости → экран «Уже идёт: <команда>, ММ:СС» с кнопкой Назад
  (alert через answerCallbackQuery невозможен: движок гасит callback сразу при получении,
  повторный answer на тот же query падает).
- Перед доктором/чисткой проверяем **update-lock** тем же механизмом, что у самого апдейта
  (`acquireUpdateLock` из `scripts/lib/update-safety.mjs`: получили — тут же отпустили и
  запускаем; не получили — «идёт обновление, подожди»). Во время обновления чужие процессы
  в репо не запускаем.
- **Отмена**: `✖ Отменить` → SIGTERM ребёнку / `systemctl --user stop` юниту → сводка «Прервано».
- **Таймауты**: доктор 10 мин (внутри бывает npm build), чистка 30 мин, поллинг юнита 60 мин
  (дальше «всё ещё идёт — journalctl …» и кнопка Назад; юнит не убиваем).
- **Рестарт моста** посреди операции: стейт и дети погибают; тап по устаревшему сообщению
  с data-вербом даёт штатное «Меню устарело — /menu», нав-вербы усыновляют. Ничего нового.

### Правила репо

- Ни одной module-level const с переведённой строкой — все подписи через `ctx.tr` в render
  (id эмодзи и alt — не переводы, им на уровне модуля можно).
- Callback-грамматика: `iva_menu:svc:o` | `c:<cmd>` (подтверждение) | `go:<cmd>` (запуск) |
  `ab` (отмена) | `up` (хендофф в update). `<cmd>` ∈ `doc|cln|mem` — ASCII-enum, ≤64 байта.
- Ошибки экрана не роняют мост (движок уже оборачивает `on()`).

### Проводка зависимостей

`telegram-poll.mjs` → `createMenu({deps})` дополняется `handleUpdateCheck` (уже экспортирован)
и путями (`root`, `envPath`, `dataDir` уже есть в deps; vaultDir резолвим из env как в
`bin/iva.mjs:404`).

## Тесты

`menu-screens.test.mjs` (+ по образцу соседей):

- рендер `svc` на ru/en, состав кнопок; кнопка в root и регистрация sid в движке;
- экран подтверждения для каждой команды;
- busy-гейт: вторая команда при занятости — alert, экран не ломается;
- запуск: подменённый spawn/execFile через инъекцию — прогресс-эдит с custom_emoji entity;
- даунгрейд эмодзи: первый эдит с entity получает 400 → следующие без entity, с fallback;
- сводка успеха/провала (exit 0 / non-zero), парс финальной строки cleanup;
- отмена: SIGTERM позван, сводка «Прервано»;
- правило i18n: без module-level переводов (существующий тест-паттерн).

## Вне скоупа

- Рефакторинг двух существующих реализаций custom-emoji-лоадера в общий модуль.
- Прогресс ночного цикла по журналу в реальном времени (только elapsed + итог).
- Логи файлом в чат при провале.
- Изменения самого `/update`-флоу.
