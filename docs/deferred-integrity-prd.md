Status: deferred after the 2026-08-16 integrity safe-stop.

This document records future work. It does not authorize production changes.

## 1. Future-wave goal

Remove the remaining confirmed integrity, installer, configuration, and boundary gaps without reopening the accepted safe-stop. Preserve local bytes, explicit ownership, fail-closed state classification, and honest user-visible outcomes.

The integration candidate contains the accepted Bridge series through `273b01b`, D10 through `58f1388`, and runtime updater through `65036f6`. These series cover D3, D4, D9, D10, M9, M10, M11, M16, M17, and X1. The common integration gate still decides whether this candidate becomes the safe-stop.

## 6. Cross-wave risks

- Lock and takeover changes can deadlock updates or admit concurrent owners.
- Filesystem generation changes can strand the only active path.
- Canonical path changes can split or strand existing state.
- Strict state classification can reject legacy bytes and needs explicit migration.
- Boundary changes can break documented host or group behavior.
- Installer pinning can fail across platforms without an artifact matrix.
- D10 retained debt can increase disk use until a proven safe collector exists.

## 7. Temporary operating rules

- Do not run two updaters at once.
- Do not run repair.
- Do not perform new public installations.
- Use the Telegram menu only in a private chat.
- Never expose `.env` or bearer values in chat or test output.
- Do not change timezone or context-window settings by hand.

These rules reduce exposure. They do not close the deferred findings.
